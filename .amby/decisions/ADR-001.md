# Decision records are files, not a database

## Context

Decisions need to be cited by ID, diffed in review, and read by any assistant. The project is a CLI
that already keeps every artifact as markdown under version control.

## Decision

One markdown file per decision under `.amby/decisions/`, with frontmatter parsed by the existing
`gray-matter` and `zod`. No database, index service or new dependency.

## Alternatives

- A SQLite or JSON store — not reviewable in a pull request and needs a reader tool (Principle 2).
- One long decisions document — assistants would load all of it on every run (Principle 3).

## Consequences

- Records merge, diff and blame like code, and cost zero tokens until cited.
- Consistency is checked by `ambykit analyze`, not enforced by a store.
