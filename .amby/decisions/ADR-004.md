# The Fleet view is hand-rolled on the existing terminal layer, not Ink

## Context

Spec 029 adds a Fleet view to the interactive dashboard and asked, before any view code (US-8, FR-015), whether to build it on
the existing hand-rolled layer (`fullscreen.ts`, pure reducer and renderer) or on Ink 7. Evidence is in
`specs/029-fleet-control-room/research.md`. Spike A (hand-rolled) is measured: 45 source lines, about 0.007 ms per 10-lane frame,
no new dependency, restore already covered. Spike B (Ink) could not be built in this session (no network).

## Decision

Build the Fleet view hand-rolled on the existing layer: a pure renderer and a pure reducer slice inside `runFullscreen`, with a
small width-aware layout module. Add no dependency.

## Alternatives

- **Ink 7** — a component model, but React, a reconciler and Node 22 for a view that is a list of rows; feature 006 already
  rejected it on footprint and 029 does not change that. Adopting it would need an exception to the dependency cap.
- **A different TUI library (blessed and similar)** — larger and unmaintained; rejected in feature 006.

## Consequences

- Runtime dependencies stay `gray-matter` and `zod`; terminal restore stays the one tested path (feature 017).
- Icon width stays our problem: Nerd and a few unicode glyphs have ambiguous width, so every glyph is paired with a state word and
  the Nerd set reserves two cells.
- The Ink comparison was not measured. If the Fleet view later grows well past a list (032's tabs, search, forms), revisit with a
  measured Ink spike and supersede this record.
