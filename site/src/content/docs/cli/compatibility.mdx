AmbyKit's **author-once, emit-per-tool** design means one neutral source becomes each assistant's
native format. These are the selectable targets and their command surface. Several targets share one
emitter (VS Code extensions, sibling CLIs).

## Selectable targets

| Target id | Assistant | Command surface |
|---|---|---|
| `claude` | Claude Code (CLI) | `commands` |
| `claude-vscode` | Claude Code (VS Code) | `commands` (alias of `claude`) |
| `copilot` | GitHub Copilot (VS Code) | `commands` |
| `copilot-cli` | GitHub Copilot CLI | `skills` |
| `opencode` | OpenCode | `commands` |
| `cursor` | Cursor | `commands` |
| `cursor-cli` | Cursor CLI | `none` (rules-only) |
| `antigravity` | Antigravity (IDE) | `skills` |
| `antigravity-cli` | Antigravity CLI | `skills` (reuses Antigravity) |
| `codex` | Codex CLI | `skills` |
| `gemini` | Gemini CLI | `commands` (TOML) |
| `llxprt` | LLxprt Code | `commands` (TOML) |
| `qwen` | Qwen Code | `commands` |
| `kilo` | Kilo Code | `commands` |
| `augment` | Augment Code | `commands` |
| `windsurf` | Windsurf | `workflows` |
| `kiro` | Kiro (IDE + CLI) | `skills` |
| `pi` | Pi | `skills` (alias of `codex`) |

## Where files land (additional targets)

| Target | Commands | Format | Args placeholder | Rules |
|---|---|---|---|---|
| Gemini CLI | `.gemini/commands/*.toml` | TOML: `prompt`, `description` | `{{args}}` | `GEMINI.md` pointer region |
| LLxprt Code | `.llxprt/commands/*.toml` | TOML: `prompt`, `description` | `{{args}}` | `LLXPRT.md` pointer region |
| Qwen Code | `.qwen/commands/*.md` | `description`, `argument-hint` | `{{args}}` | `AGENTS.md` |
| Kilo Code | `.kilo/commands/*.md` | `description` | `$ARGUMENTS` | `AGENTS.md` |
| Augment Code | `.augment/commands/*.md` | `description`, `argument-hint` | `$ARGUMENTS` | `AGENTS.md` |
| Windsurf | `.windsurf/workflows/*.md` | none (12,000-character limit) | reworded as prose | `AGENTS.md` |
| Kiro | `.kiro/skills/<name>/SKILL.md` | `name`, `description` | reworded as prose | `AGENTS.md` |
| Pi | `.agents/skills/<name>/SKILL.md` | same files as Codex, written once | reworded as prose | `AGENTS.md` |

Every format above is taken from the vendor's own documentation or source. Unverified surfaces
(Amazon Q, which is now Kiro CLI; Kiro prompt files; persona files) are not emitted. Windsurf's
`.windsurf/` is a legacy path that current builds still read. See
[tool compatibility](https://github.com/ambystechcom/AmbyKit/blob/main/docs/tool-compatibility.md)
for sources.

## Where files land

| Concern | Claude Code | OpenCode | Copilot (VS Code) | Copilot CLI | Cursor | Cursor CLI | Antigravity | Codex CLI |
|---|---|---|---|---|---|---|---|---|
| Rules file | `CLAUDE.md` (+`@AGENTS.md` bridge) | `AGENTS.md` | `.github/copilot-instructions.md` + `AGENTS.md` | same as Copilot | `.cursor/rules/*.mdc` + `AGENTS.md` | Cursor config + `AGENTS.md` | `AGENTS.md` + `.agents/rules/*.md` | `AGENTS.md` |
| Commands | `.claude/commands/amby/*.md` | `.opencode/commands/*.md` | `.github/prompts/*.prompt.md` | **skills** | `.cursor/commands/*.md` | none | **skills** — `.agents/skills/*/SKILL.md` (shared with Codex) | **skills** — `.agents/skills/*/SKILL.md` |
| MCP file | `.mcp.json` | `opencode.json` → `mcp` | `.vscode/mcp.json` (`servers`) | `~/.copilot/mcp-config.json` (`mcpServers`, user) | `.cursor/mcp.json` (`mcpServers`) | reads `.cursor/mcp.json` | `mcp_config.json` (`mcpServers`, user) | `.codex/config.toml` — not written (out of scope) |

:::note
Claude Code does not read `AGENTS.md` natively — AmbyKit emits a `CLAUDE.md` whose first line is
`@AGENTS.md` so there is a single shared rules source. User-level MCP files (Copilot CLI, Antigravity)
are written only with explicit consent. Codex's skills have no argument-placeholder convention, so
AmbyKit rewrites `$ARGUMENTS` into instruction prose instead of leaving a literal token.
:::
