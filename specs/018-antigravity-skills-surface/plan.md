# Implementation Plan — Antigravity skills surface

> The HOW. Satisfies every `FR-###` in `@spec.md` and honors `@../../.amby/constitution.md`.
> No `ui.md`: this is an emitter/CLI change with no new screens (output is console lines only).

## Technical context

- **Stack:** TypeScript ESM/NodeNext, Node ≥ 20, Vitest. No new dependencies.
- **Key libraries:** none. Reuses `SkillsEmitter` (016), the collision guard in `src/core/emit.ts`
  (016), `applyFiles`/`backupFile` in `src/cli/io/fsops.ts`, and `ambykit restore`.
- **Constraints driving choices:**
  - P1/P2: Antigravity becomes a thin `SkillsEmitter` subclass; no second skills renderer.
  - P4: the skill format (`name` = directory, lowercase/digits/hyphens; `description` required) comes
    from antigravity.google/docs/skills/ (checked 2026-11-04). The slash name the CLI derives from a
    skill is **not** documented precisely enough to rely on: see Risk R2 and the Phase 0 check.
  - P5: snapshot test per Antigravity target, a test per FR.
  - P7: removal is opt-in and reversible (backup + `ambykit restore`); nothing user-level is written.
- **Prerequisite (R1):** the skills emitter, the `sharedOutputs` helper and the collision guard
  exist only on branch `016-agent-surface-expansion`, not on `main`. This feature is **stacked on
  016**: rebase `018-antigravity-skills-surface` onto it (the branch holds spec files only, so no
  conflicts) and merge 016 first.

## Architecture

```
AntigravityEmitter extends SkillsEmitter      commandDir = .agents/skills   (was: BaseEmitter, workflows)
AntigravityCliEmitter extends AntigravityEmitter   (unchanged; differs only in toolId → `--agent=`)
        │  same bytes as CodexEmitter except `--agent=<id>`
        ▼
core/emit.ts  buildEmittedFiles ── collision guard (016) + SELF_REPORT_PRIORITY ["codex","antigravity","antigravity-cli"]
        ▼
cli/io/fsops.ts applyFiles ── protectForeign: skip an existing file lacking the GENERATED notice   (FR-016)
        ▼
core/legacy.ts  legacyWorkflowFiles(root, config)  (pure listing of stale generated workflows)
cli/sync.ts     --prune-legacy → back up each stale file, then delete it                          (FR-005)
cli/check.ts    reports stale files + shared owners by directory (not drift)                      (FR-007/008)
```

- **Boundaries:** emitters stay pure (specs → `EmittedFile[]`); the priority rule is a pure function
  in `emit.ts`; the only new I/O is the foreign-file read in `applyFiles` and the prune in `sync`
  (edges, P/AGENTS "side effects at the edges").
- **Workflows surface stays** in `CommandSurface` and `WindsurfEmitter` (Windsurf still uses
  `.windsurf/workflows`); only Antigravity leaves it.
- **Self-report identity (US-3):** `$AGENT` is baked from `toolId` per emitter, so Codex and
  Antigravity differ only in `--agent=<id>`. The 016 guard already tolerates such a difference but
  uses "last in config order wins". It changes to a fixed rank: `codex` > `antigravity` >
  `antigravity-cli`; ids not in the list keep the old rule. The winner is independent of config order.
- **Foreign-file guard (FR-016):** `EmittedFile.protectForeign?: boolean`, set by `SkillsEmitter`
  for its command files. `applyFiles` leaves an existing file without `GENERATED by AmbyKit` alone and
  records it in a new `WriteResult.skippedForeign`. `sync` warns; `check` reports it and is not
  healthy. Applies to every `SkillsEmitter` target (Codex, Kiro, Pi, Antigravity); emitted bytes are
  unchanged, so FR-011 holds. Copilot CLI (skills by helper, not subclass) is left as is.
- **Stale detection (FR-005/006):** a file is stale only if it is `.agents/workflows/amby.<id>.md`
  for a known phase id **and** contains the generated notice, and only when `antigravity` or
  `antigravity-cli` is selected. A user's own workflow, or one that merely shares the folder, never
  matches.
- **Cost:** emitted bytes per skill equal Codex's; stale scan reads ≤ 11 small files, only when an
  Antigravity target is selected. No model tokens (P3).

## Phased approach

- **Phase 0 — Research & base:** rebase onto 016. Verify against Antigravity's skills docs and, if
  available, a live install: (a) skill frontmatter keys (`name`, `description` only), (b) the slash
  name a skill gets in the CLI (`/amby-specify`?) and whether the docs/README can state it, (c) the
  cutoff scope for the CLI. Record in `research.md`, update `docs/tool-compatibility.md` first (P4).
- **Phase 1 — Foundation:** priority rule in `emit.ts`; `protectForeign` + `skippedForeign` in
  `fsops.ts`; `sharedOutputs` grouped by command directory instead of emitter (Antigravity and Codex
  are different emitters on one directory); export `backupFile`; `legacyWorkflowFiles` in
  `core/legacy.ts`. Each with unit tests.
- **Phase 2 — US-1 (P1):** switch `AntigravityEmitter` to `SkillsEmitter`; update the Antigravity
  golden fixtures and add the snapshot test; confirm the `$ARGUMENTS` rewording (FR-003).
- **Phase 3 — US-2 (P1):** `sync --prune-legacy`, stale reporting in `sync` and `check`, usage text;
  e2e over a project synced with the old release (fixture of old workflow files).
- **Phase 4 — US-3 (P2):** collision/priority tests (Antigravity with Codex, Pi, IDE+CLI, both
  orders, a genuine content difference), shared-owner listing, deselect-keeps-files.
- **Phase 5 — US-4 (P2):** byte-identity test for all non-Antigravity goldens; dashboard recognition
  test; docs (`tool-compatibility.md`, README, `cli-reference.md`, `workflow.md`, `AGENTS.md`
  command-surface line, site compatibility, CHANGELOG, 016 status note); `ambykit sync` self-check.

## Risks & decisions

- **R1, stacked on 016 (high).** Without 016 merged first this feature cannot compile against main.
  Mitigation: rebase now; merge in order 016 → 018. If 016 is rejected, 018 must carry the skills
  emitter itself.
- **R2, unverified slash name.** Antigravity says the CLI turns skills into slash commands but not
  how a name like `amby-specify` maps (today Claude/OpenCode users type `/amby.specify`). The docs
  and README must not promise `/amby.specify` for Antigravity until Phase 0 confirms it. SC-001's
  live check is the gate; if no install is available, waive it explicitly as in 016/T025.
- **R3, behavior change for existing Antigravity users.** `sync` stops writing workflows and starts
  writing skills; nothing is deleted without `--prune-legacy`. Documented in CHANGELOG under Changed.
- **R4, guard scope.** `protectForeign` also protects Codex/Kiro/Pi skills from being overwritten.
  Accepted: same rule everywhere is simpler than a per-target flag. Copilot CLI is excluded for now.
- **R5, dashboard distinction lost** when Antigravity shares files with Codex (assumed in the spec).
  Mitigation: documented; `--agent=` falls back to the winning id only for the shared file.
- **Decision:** deleting stale files goes through `.amby/backups/` so `ambykit restore <file>`
  undoes it (P7), rather than a hard delete.
- **No clarify needed.** Spec gaps found: none blocking. Open check only: the CLI cutoff scope (Phase 0),
  which does not change the design because both targets move now (FR-015).
